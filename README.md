# Kochia — SFPA Digital Health PWA

A bilingual (Arabic / English) Progressive Web App providing confidential sexual and reproductive health information, interactive tools, and service pricing for SFPA Sudan clients.

## Website layer (CEMOPLAF-style)

The app is now a full SFPA website as well as the Kochia PWA. Layout, navigation, and flows follow the CEMOPLAF Ecuador site (cemoplaf.org.ec) as a reference, in SFPA's own brand (navy `#253D87` and red `#EA2324`, sampled from the logo). It stays a React + Vite SPA on Vercel; nothing here depends on WordPress.

### Routes

| Path | Page |
|---|---|
| `/` | Home: hero, quick access, stats, specialties tabs, service catalogue, programmes, news, CTA |
| `/services`, `/services/:slug` | Service catalogue in four groups, and one page per service with linked prices |
| `/services/prices` | Full price list (original Kochia view) |
| `/clinics` | Clinic directory with city filter, Leaflet/OpenStreetMap map, WhatsApp, directions, and booking |
| `/book` | Six-step booking demo (clinic, service, day, time, details, review) with confirmation, .ics export, and WhatsApp share |
| `/telehealth` | Remote support by WhatsApp and phone; video consultations marked "coming soon" |
| `/programmes`, `/news`, `/news/:slug`, `/about`, `/contact`, `/donate`, `/privacy` | Organisation pages |
| `/learn`, `/tools`, `/faq` | Original Kochia articles, tools, and FAQ |

Routing uses the History API (`src/lib/router.jsx`), so no dependency was added for it. `vercel.json` already rewrites all paths to `index.html`, and the service worker serves it offline.

### Where content lives (CMS-ready)

| Content | File |
|---|---|
| Organisation details (email, address, hours, socials, donation link) | `src/content/site.js` |
| Service catalogue | `src/content/specialties.js` (links to prices in `src/data/services.js` via `priceIds`) |
| Programmes | `src/content/programmes.js` |
| News | `src/content/news.js` |
| Website UI strings (EN/AR) | `src/data/ui.js` |
| Clinics | `src/data/facilities.js` (add `lat`/`lng` to put a clinic on the map) |

Content uses `{ en, ar }` pairs and plain arrays, so a headless CMS (WordPress REST, Strapi, or similar) can later return the same shape without frontend changes.

### Placeholders still to replace

Anything unconfirmed renders with a visible orange "To be confirmed", "Placeholder", or "Sample" marker rather than invented data. Items to supply: head-office address, email, opening hours, social links, donation payment link, clinic addresses/hours/phones/coordinates, mission and vision, founding year and history, programme descriptions, news stories, and photography. The Arabic copy needs review by an SFPA Arabic speaker.

### Privacy in the demo flows

The booking flow keeps everything in component state, never stores or transmits it, and wipes the name and phone on confirmation. Geolocation (when clinic coordinates exist) only sorts the list on the device. The contact form opens WhatsApp with a prefilled message, and the user decides whether to send it. The site uses no analytics.

## Content notes

- All health content is bilingual (Arabic RTL / English LTR). Language is toggled at runtime; `dir` and `lang` are set on `<html>`.
- Prices in `services.js` are from the SFPA Medical Services Registry. `price: null` means the service is free.
- Clinic records in `facilities.js` are placeholders — populate with verified data before go-live.
- The app is fully offline-capable once loaded (Workbox pre-caches all JS, CSS, and HTML; Google Fonts are cached on first network fetch).

## Architecture notes

- All translatable strings live in `src/data/translations.js` — white-label by editing one file.
- Content (articles, videos, tools, FAQs) lives in `src/data/` — swap without touching components.
- Components are stateless where possible; state lives in `App.jsx`.
- RTL layout is driven by a `dir` attribute on the root element; no CSS duplication needed.

## Deploy to Vercel via GitHub

1. Push this repository to GitHub.
2. Go to [vercel.com](https://vercel.com) → New Project → import the GitHub repo.
3. Vercel auto-detects Vite. Accept the defaults (build command: `vite build`, output directory: `dist`).
4. Deploy. The `vercel.json` rewrite rule ensures client-side routing works correctly.

## Voice mode

Articles, open FAQ answers, and each tool question and result have a Listen button. The buttons appear only in browsers that support speech. Nothing is ever read aloud without a tap. In a tool, tapping Listen once makes the following questions (with their numbered options) and the result read automatically until the user taps Stop or closes the tool. This choice is not remembered between sessions.

Voice mode uses the browser's built-in text-to-speech (Web Speech API). Nothing is sent to SFPA or any backend, and on-device voices are chosen over cloud voices where both exist. Quality depends on the phone: most Android devices include an Arabic voice in Google text-to-speech, but some need it downloaded under Settings → Text-to-speech. If no voice is installed for the current language, the app says so under the Listen button. Voices read Modern Standard Arabic, not Sudanese dialect.

## Constraints (do not add)

- No login or authentication
- No analytics platform
- No backend database (Supabase, Firebase, Odoo, OpenEMR, etc.)
- No real WhatsApp / Turn.io API integration (the FAB opens a `wa.me` link only)
- No fabricated clinic coordinates, phone numbers, or prices not confirmed by SFPA
- No real booking backend until SFPA approves data safeguards (the booking flow is a demo)

## Customisation checklist before go-live

| Item | File | Field |
|------|------|-------|
| WhatsApp number | `src/data/facilities.js` | `WA_NUMBER` |
| Facility coordinates | `src/data/facilities.js` | `FACILITIES` array |
| Organisation name | `src/data/translations.js` | `orgName` |
| PWA app name | `vite.config.js` | `manifest.name` |
| Theme colour | `vite.config.js` | `manifest.theme_color` |
| App icons | `public/icons/` | Replace `icon-192.png`, `icon-512.png` |

## Before deploying

1. **Configure contact details** — open `src/config.js` and set:
   - `WA_NUMBER` — WhatsApp number in international format, digits only (e.g. `'24912345678'`)
   - `CALL_CENTRE` — telephone number shown as the call-centre contact
   
   If either value is left empty (`''`), that contact button shows a placeholder rather than a broken link.

2. **Add clinic data** — open `src/data/facilities.js` and fill in real addresses, coordinates, phone numbers, and service lists for each clinic.

3. **Add PWA icons** — generate `public/pwa-192.png` and `public/pwa-512.png` from `public/favicon.svg` using a tool such as [Squoosh](https://squoosh.app) or [PWA Asset Generator](https://github.com/elegantapp/pwa-asset-generator). Also generate `public/apple-touch-icon.png` (180×180 px).

4. **Add videos** — open `src/data/videos.js` and add real video URLs.
